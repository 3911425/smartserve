# 设计决策记录

| 编号    | 选择                          | 原因                                                | 代价 / 演进                             |
| ------- | ----------------------------- | --------------------------------------------------- | --------------------------------------- |
| ADR-001 | Java后端单仓库 + Vue前端      | 匹配Java/AI应用路线，业务与Agent一起审查            | 模块数增长再拆服务，当前不为拆分而拆分  |
| ADR-002 | PostgreSQL同时保存业务与向量  | 减少双数据库运维，可按业务条件检索                  | 扩大语料后评估独立向量/全文服务         |
| ADR-003 | BGE中文本地ONNX               | DeepSeek聊天Key不能直接当Embedding服务；无需额外Key | 加大JAR与内存成本，模型升级要重建向量   |
| ADR-004 | Supervisor + 受控域专家       | 工具范围、输入输出、终止路径清晰                    | 不是自由自治群聊，适合可审计客服        |
| ADR-005 | MCP最小HTTP协议层             | 展示工具发现与域内授权的真实调用                    | 企业互通要维护中的SDK/OAuth和一致性测试 |
| ADR-006 | 退款草稿与确认分开            | 避免Agent自行执行业务后果                           | 多一步用户确认，换来明确授权            |
| ADR-007 | 用户+订单+整单类型幂等        | 原因文字变化不能造成第二次退款                      | 部分退款需订单明细、额度与退款批次模型  |
| ADR-008 | 人工服务升级单                | 用户需求是异步人工处理和回写                        | 非实时在线人工聊天                      |
| ADR-009 | 持久数据库检查点              | 服务重启可恢复，Redis丢失不丢历史                   | 多节点租约还需fencing与恢复演练         |
| ADR-010 | 证据门槛+引用+独立审查        | 减少无据生成，失败可回原文                          | 额外模型成本；仍无法保证零幻觉          |
| ADR-011 | 词法/向量混合与可解释重排     | 中文小语料可理解、可实验                            | 不是训练型神经reranker，大语料要优化    |
| ADR-012 | 本机PG无向量扩展的独立profile | 利用用户已有数据库，仍保留正式栈                    | UI必须明确JVM检索，不能冒称pgvector     |
| ADR-013 | AI辅助代码与真实验证记录      | 让学习、修改与展示可追溯                            | 不捏造独立手写、性能成绩或商业部署经验  |

暂不采用LLM Wiki：语料很小，检索来源已清晰，加入知识编译层会增加版本与审核成本。暂不多模态故障诊断：项目没有足够图像证据、模型接口和故障数据。暂不独立Workflow Runtime：LangGraph4j与业务任务日志已满足当前边界。暂不自动学习人工结论：人工回复需审查后才进入知识原料。

工程演进优先级：真实认证与租户隔离 → 租约fencing与外部支付幂等 → 规范化账务与数据库迁移 → 检索负样本与神经reranker对比 → 大规模全文检索与成本限额。每项以业务压力或实验结果为触发条件。
