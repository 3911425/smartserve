# 运维与故障演练

本手册默认本机或隔离开发环境。演练前记录所用profile、数据库名、运行版本、模型开关，禁止在不清楚连接对象时清库或删卷。

## 启动排错顺序

1. 前端打不开：确认5173监听、`.local/frontend.out.log`或容器frontend状态。
2. 登录页报服务连接失败：确认`http://localhost:8080/api/status`、后端启动日志、数据库连接。
3. 后端启动失败：看日志中的第一个实际异常，区分密码/端口/Flyway/扩展权限/模型Key，不能删数据库碰运气。
4. 刚启动知识加载慢：BGE在进程内加载，资料改变需要重新算向量，等待索引就绪；Tomcat监听日志不代表ApplicationRunner已全部完成。
5. 登录401：确认正在使用哪个库，初始密码只在首次建账号时生效；改过密码后`.env`不会覆盖它。
6. 写操作403：检查Cookie、CSRF和访问域名，统一用localhost或统一用127.0.0.1，避免两套host-only Cookie混用。
7. Agent失败：先查run事件、model_call，再查MCP、检索候选；不能把全部问题归结为提示词。

## 三类数据备份

源码、知识和评测集用Git；`.env`用私密配置备份，不能提交。数据库用逻辑备份，Docker卷并不是版本管理。H2文件只有进程停止后才能按文件复制；评测数据库可以保留夹具复现，不能混入正式业务库。

本机 PostgreSQL 使用匹配版本的`pg_dump -Fc`，用`pg_restore --list`检查备份目录；恢复到新数据库再验收，不直接覆盖当前库。容器PG可通过`docker compose exec -T postgres pg_dump`备份，密码通过环境或私密凭证渠道提供，不写进公开命令历史。一次成功导出并不等于已经演练过恢复。

V2首次迁移前，本机已建立私有逻辑备份`.local/backups/native-before-v2.dump`并检查目录清单，详见验证报告。本文件不进入Git。数据库开始使用Flyway后不要修改已执行迁移文件，后续结构变动新增V3等迁移。

## Docker下载不稳定时的产物封装方案

普通Compose从源码在容器中运行Maven和npm，需要下载基础镜像与依赖。Docker构建缓存与本机`.local/m2`是两套缓存。本次源码构建在Maven Central响应体下载中断处失败；加入BuildKit依赖缓存和重试后仍遇到传输中断，所以没有记录成源码镜像构建通过。

本机已经通过Maven验证并生成JAR，前端也已构建。可以直接将这两个产物封装进运行镜像，仍然启动相同的五个服务：

```powershell
cd E:\SmartServe
docker compose -f docker-compose.yml -f docker-compose.artifact.yml --profile app up -d --build --wait
```

这条命令要求`backend/target/smartserve-backend-2.0.0.jar`和`frontend/dist`为当前源码的最新构建结果，不会替你重新编译。两个`Dockerfile.artifact`只接收白名单产物，密钥和本机依赖缓存不会打进镜像。镜像单独标记为`2.0.0-local`，与普通源码构建标签分开。

本次已用这种方式验证Linux BGE加载、五服务就绪、前端/API/图片访问、匿名订单拒绝与MCP代理隔离。停止使用：

```powershell
docker compose -f docker-compose.yml -f docker-compose.artifact.yml --profile app down
```

日常学习继续使用启动指南里的本机方案即可。源码构建成功前，不应在报告中把产物封装通过改写为“从零下载并构建通过”。

## 故障演练表

| 演练            | 操作与观察                               | 预期 / 边界                                             |
| --------------- | ---------------------------------------- | ------------------------------------------------------- |
| 购买响应丢失    | 在隔离客户端以相同requestKey重试同一购买 | 同一订单，单次扣款；换键代表新请求                      |
| 库存竞争        | 多个客户同时抢最后一件                   | 最多一笔成功，其他整体回滚；有限样本不代表生产QPS       |
| 重复退款审核    | 两个管理员或并发请求批准同一申请         | 唯一资金流水，一次返还；版本和终态处理可解释            |
| Redis停止       | 混合模式停止项目redis，继续检索          | 回源重算，可能变慢；资金不受检索缓存影响                |
| Rabbit停止      | 新建客服任务，查看QUEUED                 | 持久任务保留，恢复扫描重投；不是购买接口也进队列        |
| 重复消息        | 相同runId多次投递                        | CAS领取仅一个活跃拥有者                                 |
| worker中断      | 中途停止后端，再启动                     | 租约过期后恢复，最多3次领取；可能重复付费请求           |
| 任务取消        | 回答生成时点停止                         | 状态CANCELLED，旧执行不得保存答案；已发出的模型可能计费 |
| SSE断开         | 断开再以Last-Event-ID续读                | 从持久事件游标补读；不是重新创建任务                    |
| 模型503         | 本地协议桩先503后成功                    | 两次attempt可见，失败Token未知；不能隐藏重试            |
| LangSmith不可用 | 开追踪但远端请求失败                     | 本地轨迹保留，标记导出失败；业务结果不因导出失败回滚    |
| 知识错误        | 修改资料、审核、重索引、跑评测           | revision变化、旧缓存失效；当前不是跨实例原子发布        |

某一演练只有对应测试或执行记录存在时，才可以在报告里写“已验证”。表中列出的是方法，不是自动完成声明。

## 安全与上线前缺口

当前有会话、CSRF、后端角色与归属校验、输入校验、登录失败锁定、受限工具与私密配置隔离。下一次上线前仍需HTTPS、安全Cookie、反向代理与网段限制、分布式限流/反滥用、管理员账号恢复流程、日志留存和敏感数据删除策略、备份恢复演练、容量与故障测试。真实支付/退款必须补回调验签、幂等对账及支付状态机，不能只把模拟钱包按钮换个名称。

模型请求可能将客户输入和有限业务事实发送给模型供应商；当前仅订单工具删除收件联系方式，**没有完备的用户自由文本敏感信息识别**。不要把“LangSmith脱敏导出”误称为所有第三方传输均完全脱敏。公网版需要清晰告知、最小化传输与输入处理。

运行事件可能包含检索内容和问题相关工具参数，属于管理数据。本版本没有后台清理/归档任务，持续运行需设计TTL、分区或归档，避免无限积累。
