# 运维与故障演练

更新：2026-10-23 · 适用业务版本 `2.1-20261023`。日常启停看[启动指南](01-启动与账号.md)；本页用于排错、备份和隔离演练。先确认连接的数据库、端口、运行版本和模型开关，再操作。

## 先检查什么

| 现象 | 按顺序检查 |
| --- | --- |
| 网页打不开 | 访问的是5173；本机前端日志或容器frontend状态；是否启动了正确的一套前后端 |
| 登录页提示服务连接失败 | `http://localhost:8080/api/status`；后端日志；数据库连接；不是看到登录背景就代表后端健康 |
| 账号密码错误 | 当前连接本机PG、DockerPG还是H2；输入的是初始变量等号后的值；账号是否改过密、被锁定或禁用 |
| 业务版本不匹配 | `/api/status` 应为 `businessRulesVersion=2.1-20261023`；更新整套前后端，重建JAR或应用镜像 |
| 写请求403 | Cookie和CSRF；浏览器统一用localhost或统一用127.0.0.1；角色与数据归属 |
| 数据“消失” | 核对profile、数据库URL和卷；切换数据库不会自动同步账号、订单或钱包 |
| 订单一直待发货 | 确认是否新购买；旧订单不重新随机；少量随机订单同状态可能正常；核对运行版本与事件 |
| 已送达却不能退货 | 详情的serviceOptions、签收日期、申请状态；日差0至7天；不能只看状态文字 |
| 知识加载较慢 | BGE在进程内加载，改变的资料需要嵌入；确认status中的chunks/revision就绪，监听端口不等于索引完成 |
| Agent失败 | run事件→model_call→工具/MCP→候选与accepted→护栏，按实际环节定位 |
| Docker重开仍进不去 | 引擎就绪后查容器STATUS；本机Java/Vite需脚本启动；列表保留记录不等于运行 |

本机日志：`.local/backend.out.log`、`.local/backend.err.log`、`.local/frontend.out.log`。全Docker方式：

```powershell
cd E:\SmartServe
docker compose --profile app ps -a
docker compose --profile app logs --tail 100 backend
```

`logs -f backend` 可持续跟随，Ctrl+C只停止跟随。不要同时运行两套占用8080/5173的应用。

## 代码更新后怎样避免旧包

本机和混合方式共享 `start.ps1`：默认重新打包；`-SkipBuild` 只有在源码与JAR的SHA-256记录一致时才复用，记录缺失或不符就重建。前端还会检查业务协议版本。

全Docker方式改源码后运行 `docker compose --profile app up -d --build`。`restart`只重启现有容器，不把新源码编进镜像。普通源码构建与五服务运行已经通过验证；已有依赖缓存参与了构建，不能说成“无缓存从零下载验收”。

本机Maven缓存和Docker BuildKit缓存是不同位置。后端构建使用依赖缓存和下载重试；下载失败先看网络错误，恢复后重试，不要改业务数据。

还保留产物封装备用配置 `docker-compose.artifact.yml`。仅在本机已经从当前源码构建好 `backend/target/smartserve-backend-2.0.0.jar` 和 `frontend/dist` 时使用：

```powershell
docker compose -f docker-compose.yml -f docker-compose.artifact.yml --profile app up -d --build --wait
```

它不会重新编译源代码，镜像标记为 `2.0.0-local`。停止时使用同样的两个 `-f` 参数，将 `up ...` 换为 `down`。普通源码方式是日常部署入口；备用方式不能掩盖过期产物。

## 数据位置和备份

源码、知识、固定评测集由Git管理；私密配置 `.env`、日志和数据库备份不进入Git。实际路径和卷名见[启动指南](01-启动与账号.md)。备份卷不等于给数据库做了可验证的逻辑备份。

| 数据 | 备份和恢复要点 |
| --- | --- |
| 本机PostgreSQL | 匹配版本的pg_dump导出，pg_restore检查清单；恢复到新数据库验证 |
| Docker PostgreSQL | 容器内pg_dump到文件，再用compose cp取出；不要依赖旧版PowerShell重定向二进制输出 |
| H2 | 停止使用该库的进程后复制文件，不能边写边直接复制 |
| Redis/RabbitMQ | Redis缓存可重算，任务主状态在DB；其卷不是钱包或订单的备份 |
| 知识与配置 | 保留知识版本、模型ID、策略和结果；改Markdown后重新索引，启动也会自动加载 |

本机PG示例，要求PG工具已在PATH；`-W` 在终端提示输入密码：

```powershell
cd E:\SmartServe
New-Item -ItemType Directory -Path .local/backups -Force | Out-Null
pg_dump -h 127.0.0.1 -p 5432 -U postgres -d smartserve -W -Fc -f .local/backups/native-backup.dump
pg_restore --list .local/backups/native-backup.dump
```

Docker PG示例，使用容器自己的初始化用户名，不把密码写进命令：

```powershell
docker compose exec -T postgres sh -c 'pg_dump -U $POSTGRES_USER -d smartserve -Fc -f /tmp/smartserve-backup.dump'
docker compose cp postgres:/tmp/smartserve-backup.dump .local/backups/docker-backup.dump
pg_restore --list .local/backups/docker-backup.dump
```

每次备份使用新的文件名，保留时间和来源库。恢复演练新建目标库，恢复后检查账户、订单/流水、退款历史、迁移版本和知识索引；验证后再决定是否切换连接，不能直接覆盖日常库。换绑定目录也需要迁移数据，旧命名卷不会自动搬过去。

两套业务PG在V3前已导出并检查清单，文件为 `.local/backups/before-business-logic-*.dump`；**尚未完成恢复演练**。Flyway当前迁移到V3（refund_history），后续改表新增V4等文件，不修改已执行迁移来“修校验和”。

## 故障演练怎么做

下面是实验方法，只有存在测试或执行记录才算已经验证。停服务、崩溃和数据异常实验放在隔离环境，当前证据看[验证报告](06-评测与验证报告.md)。

| 演练 | 操作与观察 | 预期与边界 |
| --- | --- | --- |
| 购买响应丢失 | 同键、相同内容重试 | 同订单和配送状态，单次扣款；换键代表新购买 |
| 库存竞争 | 多客户抢最后一件 | 最多一笔成功，其余整体回滚；有限样本不是生产TPS |
| 退款重提 | 撤回或驳回后改原因，再用旧版本确认 | 保留历史，新版本须重新确认；旧版本409 |
| 重复审核 | 并发批准，再发相反结论 | 一次返还；同终态重放幂等，相反结论409 |
| Redis不可用 | 停隔离项目redis后检索 | 回源重算，不影响钱包库存正确性 |
| Rabbit不可用 | Rabbit模式提交客服任务 | 持久任务在DB，恢复扫描重投；购买不经过MQ |
| 重复消息 | 多次投递同runId | CAS只允许一次有效领取，不能保证外部模型恰好一次 |
| worker中断 | 中途停隔离后端再恢复 | 租约过期后重领，最多3次；旧租约不能写结果，可能重复模型费用 |
| 任务取消 | 取消后检查状态和旧租约写入 | CANCELLED，旧执行不得完成；在途请求可能计费 |
| SSE断线 | 用Last-Event-ID补读 | 从持久游标续读，不另建run；没有逐token流 |
| 模型503 | 本地协议桩先失败后成功 | 各一行model_call，未知Token为null |
| LangSmith不可用 | 隔离环境令导出失败 | 本地轨迹保留，导出失败不回滚业务 |
| 知识更新 | 审核→重新索引→固定回归 | revision变化，旧缓存不再命中；当前不是多实例原子发布 |

## 公开上线前的工作

当前有会话、CSRF、角色与归属检查、输入校验、登录锁定、受限工具和私密配置隔离。公开部署仍需HTTPS与Secure Cookie、网络隔离、全局限流/反滥用、管理员恢复、日志清理与敏感数据删除、可恢复备份、容量和多实例故障验证。真实支付还需回调验签、幂等对账和支付状态机。

模型供应商会收到客户输入和有限业务事实。订单工具不发送收件人、地址、电话，LangSmith导出不上传原始问题/正文证据；**自由文本仍没有完备的敏感信息识别**，不能把局部脱敏说成所有第三方传输完全脱敏。事件和检查点没有后台清理任务，长期运行还需留存与归档策略。
