## 检索结果与含义

当前知识库为4份版本化Markdown、46个分块，BGE-small-zh ONNX、512维；测量revision为`23805d1f5ca1`。本次指标在隔离H2/JVM检索环境运行，pgvector的实际可用性另由标准栈测试核验，**没有把同一组指标冒称同时测完三种部署环境**。

| 策略 | Recall@5 | MRR@5  | 接受且相关的正例覆盖 | 负例误接受 |
| ---- | -------- | ------ | -------------------- | ---------- |
| 向量 | 85.71%   | 0.5384 | 85.71%               | 0/16       |
| BM25 | 98.21%   | 0.7685 | 98.21%               | 0/16       |
| 混合 | 98.21%   | 0.7610 | 98.21%               | 0/16       |

Recall对每题标注相关标题计算命中比例后取平均；MRR取首次相关片段排名的倒数；接受且相关的覆盖率要求存在相关且accepted的片段。负例误接受统计领域外问题是否仍接受任何证据。

本集上混合召回高于纯向量，但**没有证明混合排序优于BM25**，其MRR略低。不能写“混合全面提升”或把98.21%称为答案准确率。数据集由项目维护者AI辅助编写，相关标题非穷尽，某些同义FAQ证据未标注；`regression/challenge`分组在开发中可见，当前不是严格盲测集。后续要增加人工复核、更难的近域负例和真正未参与调参的保留集。

## 本次实际发现的问题

1. 中文紧邻型号时，英文单词边界漏判T1/C2等，正确资料可能被范围或领域门槛拦下。已修复ASCII型号边界，并补回归。
2. 新增的钱包、账户、工单业务词没纳入领域判断。已更新识别范围，保留领域外负例检查。
3. T1电池资料排在第4条，离线回复只摘前三条，虽然检索命中却没有回答CR2032。离线受控摘录现在保留最多5条已接受资料，并增加完整任务断言。
4. 伪造引用`[S999]`被未知型号判断误认，导致错误澄清。已将引用括号边界排除，并验证仍会检索真实S1资料、不会输出伪造引用。
5. SDK的503异常状态码未必出现在message中，旧判断没进行预期重试。改为读取HTTP异常状态码，本地协议测试验证失败尝试与成功尝试分别记录。
6. 首轮模型评审只传知识片段，漏传`getProducts`工具事实，误将真实商品工具中的价格/保修/库存判为无依据。已修复评测数据契约，将`verifiedFacts`一起送评审；[首轮诊断记录](../data/evaluation/results/judge-incomplete-context.json)保留，未删除失败证据。

最后一项说明评测本身也要验证：模型评分低不一定是业务回答错，可能是评审输入漏证据。先定位原因，再修数据契约；不能靠删除难例或改标签提高分数。

7. 最后复核发现管理员可通过客户写接口代替客户操作。现在服务层显式禁止管理员取消、创建或确认客户退款，管理员只保留核验与审核；新增回归覆盖三种拒绝和客户本人合法确认。

## 真实模型与评审的范围

真实烟雾测试只有S1应急开门、C2本地/云录像、H1子设备容量三题。每题实际为主管1次、产品领域2次、护栏1次，共12次，均通过证据审查且未触发模型失败回退。这是这三次执行的结果，不能推广成每个问题固定4次或所有售后任务都已做真实模型评测。

自定义评审使用已保存的问题、参考要求、答案、知识片段和工具事实。初次3次用于诊断，补齐上下文后又3次评审，因此本次共有6次独立评审请求，不在应用AgentOps的12次里。每次评审用量在对应JSON保存，没有虚构金额账单。相同模型系列评审有偏差，参考要求也未经独立专家标注；当前不是RAGAS库执行结果。

离线32例通过的是完成状态、路由、部分关键词、必要工具和余额/申请数量边界断言，不能直接叫“Agent语义任务成功率100%”。没有关键词的用例更需要人工核对答案，离线售后模式可能倾向要求具体订单。后续应增加完整的语义验收与真实售后、多轮、注入、故障用例。

## 如何复现

先停止旧的评测服务，使用隔离端口18082，不把夹具写入日常业务库：

```powershell
cd E:\SmartServe
powershell -ExecutionPolicy Bypass -File scripts/evaluation-server.ps1
node scripts/evaluate-retrieval.mjs --gate
node scripts/evaluate-agent.mjs
powershell -ExecutionPolicy Bypass -File scripts/evaluation-server.ps1 -Stop
```

启动脚本复用当前已构建的V2 JAR；改Java后应先构建。评测客户端等待知识索引就绪。`--gate`要求这套固定集的混合Recall@5至少0.90且负例误接受为0；任务回归任一断言失败返回非零退出码。CI配置使用相同门槛，但本次没有推送触发远端CI。

需要付费模型时明确开启，默认最多3题和30次应用模型尝试：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/evaluation-server.ps1 -Online -Trace
node scripts/evaluate-agent.mjs --paid --limit 3 --max-calls 30
node scripts/evaluate-judge.mjs --paid --limit 3
node scripts/inspect-traces.mjs
powershell -ExecutionPolicy Bypass -File scripts/evaluation-server.ps1 -Stop
```

`-Trace`可选，需要有效LangSmith配置。重跑会产生新的实际调用和夹具，结果文件会更新；先保留需要比较的旧报告。评测命令不是常用启动方式，日常看项目按[启动指南](01-启动与账号.md)即可。
