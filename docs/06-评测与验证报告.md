## 最新RAG测量

本次资料为4份Markdown、46个分块，文档业务版本统一为 `2.1-20261023`，平台名称已更新为ServicePilot；BGE-small-zh ONNX，512维；知识revision **`2b16ecec24b4`**。检索集版本仍为 `2.0-20261022`，共56个正例和16个负例，未为这次文档修改重写问题或标签。

| 策略 | Recall@5 | MRR@5 | 接受且相关的正例覆盖 | 负例误接受 |
| --- | --- | --- | --- | --- |
| 向量 | 89.29% | 0.5854 | 89.29% | 0/16 |
| BM25 | 96.43% | 0.7595 | 96.43% | 0/16 |
| 混合 | 98.21% | 0.7640 | 98.21% | 0/16 |

- Recall：每题标注的相关标题在Top5中的命中比例，再对56个正例取平均。
- MRR：每题第一个相关结果的排名倒数，再取平均。
- 接受且相关覆盖：正例中至少有一条相关且accepted证据的比例，不是片段precision。
- 负例误接受：16个领域外负例中，有任意accepted证据的题数；不等于所有幻觉率。

本集混合的Recall和MRR略高于BM25，不能外推为所有语料或所有查询都更优。文档更新前的同代码测量保存在[更新前检索基线](../data/evaluation/results/baseline-2.1-before-docs/retrieval-all.json)，其revision为 `6680988e7034`，当时混合MRR低于BM25。2026-10-23主要改变知识内容；本轮只更新平台展示名，**没有修改检索算法**。本轮指标与[10月23日基线](../data/evaluation/results/baseline-20261023/retrieval-all.json)一致（旧revision `07817cd37cc8`），不能将名称调整包装成算法优化收益。

数据集由维护者AI辅助编写，标签按相关标题标注，未穷尽同义资料。regression/challenge分组在开发时可见，不是真正盲测集；负例以领域外为主，对近域混淆的覆盖仍不足。pgvector可用性已有独立基础设施验证，但没有把这组H2指标称为三种部署都测得同样质量。

## Agent评测、真实模型与追踪要分开

当前对话模型通过TokenDance调用 `deepseek-v4.1-flash`。最新售后烟雾记录在资料更新前完成：一条待发货取消咨询，路由AFTER_SALES，模型调用5次，工具为queryOrderStatus和prepareCancellation。返回可取消建议，订单仍待发货、钱包不变、未创建退款申请。这证明该次链路及只读边界，不代表全量在线任务成功率或本次新知识库的在线验收。

本次32例离线任务使用更新后的revision `2b16ecec24b4`，检查完成状态、路由、部分关键词、必要工具，以及余额/退款数量边界。覆盖多轮、未知型号、越权、伪造引用、安全升级等，但关键词和结构断言不足以证明答案在语义上全部正确。任务集版本 `2.1-20261023`；订单夹具记录实际随机状态，不假定购买一定待发货。

本地AgentOps保存过程；评测用数据、标签、断言和指标判断质量；LangSmith为可选的脱敏远程导出。三者有关联，但不能互相替代。完整在线Agent质量集、真实售后多轮覆盖和当前模型judge回归仍待补充，本次整理没有产生付费模型调用。

## 当前关键正确性证据

1. 首次购买随机配送与订单/流水/时间/事件同事务保存，同键重试稳定，旧订单不重抽。
2. OrderServicePolicy统一页面和工具边界：待发货取消、运输中人工核验、有效签收窗口内准备退货。
3. 退款准备、客户版本确认、管理员审核分开；撤回/驳回可重提，refund_history保留历史；旧版本不能确认新原因。
4. 并发购买、余额不足回滚、最后一件库存竞争、重复审核与LEGACY_DEMO不造钱均有针对回归。
5. 工单同键改内容409，管理员不能代替客户提交交易、退款确认或服务单；分页总数/归属、前端切换旧响应等已修正。
6. 明确订单号的纯物流快捷路径可0次模型；产品/售后保留有界工具循环；prepareRefund/prepareCancellation均不写交易。
7. 任务取消和过期租约不能覆盖最终结果/检查点；领域内部循环仍可能重跑，外部模型不保证恰好一次。

## 如何复现

日常启动不需要执行评测。运行前确认终端 `mvn -v` 指向Maven3.9、Java为17/21；启动脚本读取的MAVEN_EXECUTABLE并不会替终端改PATH。

先构建当前代码，评测服务脚本只复用已有JAR：

```powershell
cd backend
mvn verify
cd ..\frontend
npm ci
npm run build
cd ..
powershell -ExecutionPolicy Bypass -File scripts/evaluation-server.ps1 -Fresh
node scripts/evaluate-retrieval.mjs --gate
node scripts/evaluate-agent.mjs
powershell -ExecutionPolicy Bypass -File scripts/evaluation-server.ps1 -Stop
```

服务只用18082端口、独立H2和本地工作池，不碰日常业务数据库，默认禁用远程模型及追踪。`-Fresh`新建隔离数据库，旧夹具留在 `.local/evaluation`。客户端默认连接 `http://127.0.0.1:18082`；若手工设置过SMARTSERVE_BASE_URL，先清除该变量或明确指向评测服务，不能误写到日常库。

门槛：混合Recall@5≥0.90、负例误接受为0；任务任一断言失败返回非零。重跑会覆盖当前结果JSON，比较前先保留基线。源码或资料变化后重新运行，不能沿用旧revision的成绩。

两套PG及中间件回归：保持本机PG5432与项目Docker PG15432、Redis16379、Rabbit5672就绪，`.env`凭据有创建验证库/扩展权限，然后运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/test-business-modes.ps1
```

脚本各建 `smartserve_verify_*` 新库、执行同组核心测试，再用独立消息队列测Redis/Rabbit；测试库保留，业务库不清空。部署检查可在实际启动后设置SMARTSERVE_BASE_URL为5173，运行 `node scripts/verify-runtime.mjs --mode native`，模式按实际改为hybrid或docker；凭据默认读取 `.env`，数据库账号已改密时须提供有效值。

只有明确接受真实模型费用时，才在隔离服务上使用 `-Online`（远程导出另加 `-Trace`），再运行：

```powershell
node scripts/evaluate-agent.mjs --paid --limit 3 --max-calls 30
node scripts/evaluate-judge.mjs --paid --limit 3
```

judge默认读 `agent-online.json`，应先确认这是刚生成的目标模型结果，不能拿旧答案冒充新模型。追踪用inspect-traces脚本核查。评审请求独立计费，结束仍用evaluation-server.ps1 -Stop清理。本次没有重新执行这些付费步骤。
