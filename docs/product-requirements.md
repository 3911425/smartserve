# 产品需求与业务规则

版本 1.0 · 2026-10-10 · 项目：SmartServe 智服。业务品牌、商品、订单与服务目标均为虚构样例；工程流程面向可验证的真实业务约束设计。

## 目标与角色

客户在一个工作台完成商品了解、物流查询、售后申请与人工服务跟进。运营人员在相同工作台处理服务升级单，能核对会话、订单与处理结果。开发者通过 AgentOps 定位路由、检索和工具错误。

客户角色 customer-001：商城、本人订单、本人会话、本人运行与本人服务单。管理员 operator-001：以上功能及全部订单、全部服务单、人工处理、知识重新索引。customer-002 的样例订单专门用于验证数据隔离。默认演示免登录角色切换，服务器仍签发并校验凭证。

## 核心用户流程与验收标准

| 流程         | 输入                    | 可验收的结果                                     |
| ------------ | ----------------------- | ------------------------------------------------ |
| 商品咨询     | 点击商品咨询或描述问题  | 路由到产品专家；展示可信引用；不支持能力不能编造 |
| 物流查询     | 当前用户的完整订单号    | 返回数据库状态和运单；其他用户订单拒绝           |
| 无理由退款   | 已签收、7日内的本人订单 | 只生成待确认申请；不自动确认、不真实转账         |
| 用户确认退款 | 显式确认申请            | 复核资格、金额和归属；订单进入退款待处理         |
| 重复退款     | 并发、刷新或再次对话    | 同一整单退款只有一条申请，确认可重复             |
| 需要人工     | 主动提出或知识不足      | 提供表单；用户确认提交前不产生工单               |
| 人工处理     | 管理员认领与填写结论    | 合法状态流转；完成结果回写原会话                 |
| 恢复与查看   | 刷新页面或网络重连      | 已存消息恢复；运行事件按ID补发                   |

## 页面规格

商城为完整单页内容区，顶部统一导航，展示产品系列横幅、服务承诺、筛选、六商品卡片、详情和咨询入口。没有购物车、在线支付、真实库存或虚构销量。

订单页按状态筛选，展示产品、样例下单日期、状态与实付金额。操作通过对话触发业务专家，用户不需要理解 Agent 架构。

客服页提供会话选择、新会话、快捷问题、SSE 进度、Markdown 回答、引用原文、订单卡片、退款确认卡片、升级单表单和人工回复。默认不把开发日志塞入正常客户流程。

AgentOps 页展示真实运行统计、运行列表与时间线。用户只能访问本人运行，管理员查看全部。没有任务时显示可操作的空态，不预造监控曲线或成绩。

人工处理中心仅管理员显示。服务单字段包括问题、关联订单、联系信息、优先级、状态、处理人、内部备注和用户可见结论。查看详情时可展开原会话，避免只依赖模型摘要。

## 售后规则

- 业务时区 Asia/Shanghai。样例无理由退货窗口从签收日期计算，0≤天数≤7。
- 数据库保存金额，用 BigDecimal 处理，不允许模型传入退款金额。
- 本版仅整单退款，每订单至多一个申请；部分退款、分次退款属于后续账务模型。
- 草稿状态 AWAITING_CONFIRMATION，用户确认后 APPROVED；订单变为 REFUND_PENDING。
- 自动检查仅覆盖状态和窗口，包装、安装、损坏、仓库质检需人工核验。
- 真实支付、到账和物流操作未接入；任何界面或回答不得把样例流程描述成真实完成。

## 服务升级单规则

表单必填标题、详情、联系方式；关联订单可选且必须通过归属核验。用户选择普通或高优先级并勾选确认。幂等键由用户、会话与请求键构成，重复提交返回原单。

状态只允许 PENDING→PROCESSING→RESOLVED，PROCESSING 可以保存备注。直接从 PENDING 完成、使用旧版本覆盖、普通用户处理均被拒绝。已完成单不允许再次覆盖；需要重新处理时建立新的服务请求。完成结论不得为空，内部备注不返回客户接口。

## 非功能要求与当前限制

响应目标以可交互和可恢复为主，耗时由实际模型与本机决定，尚无商业 SLA。请求最大2000字符，工具参数、表单与状态有服务器校验；会话同一时刻最多一个执行中的任务。模型并发4，工作池4线程、64队列，SSE最多64连接。

模型不可用时产品回答降级到证据摘录，订单事实仍由业务工具返回。队列投递失败保留持久任务。图片从本地只读目录服务，文档按小节切片。移动端保留所有核心功能与可访问表单。

## 范围控制

本版不引入 LLM Wiki、多模态诊断、任意代码执行、动态 Agent 群聊、独立 Workflow Runtime、自学习自动入库或训练模型。主要价值是可解释编排、质量与业务可靠性，不以框架数量衡量深度。
