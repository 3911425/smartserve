# 启动与账号

更新：2026-10-23 · 适用业务版本 `2.1-20261023`。日常只需选下面一种方式；评测和排错命令在专门文档中。

## 先分清两件事

**运行配置决定后端连接什么；启动方式决定进程在哪里运行。** 它们不是同一个开关。

`.env` 是本机默认配置。`SPRING_PROFILES_ACTIVE=postgres-local` 表示本地 PostgreSQL；`demo` 表示 H2。Docker Compose 为后端显式设置 `postgres` 和容器内地址，所以即使 `.env` 写着 `postgres-local`，全 Docker 命令仍可运行容器方案。命令参数、Compose 环境覆盖了本机默认值。每次运行只会使用最终生效的一套连接，不会同时向两个数据库写订单。

| 后端 profile   | 主数据与向量保存                   | 向量召回                          | 异步任务与缓存                |
| -------------- | ---------------------------------- | --------------------------------- | ----------------------------- |
| demo           | H2；向量为 `vector_text` JSON 数组 | JVM 余弦扫描                      | 本地工作池；无 Redis 缓存     |
| postgres-local | 本机 PostgreSQL；同样保存向量数组  | JVM 余弦扫描                      | 本地工作池；无 Redis 缓存     |
| postgres       | 独立 PostgreSQL + pgvector         | 数据库余弦距离 TopK，有 HNSW 索引 | RabbitMQ + Redis 检索结果缓存 |

三者默认都使用**本地 BGE-small-zh ONNX、512 维**，都能做 BM25 和混合检索。H2 并非不能保存向量：它保存数字数组，Java 负责算相似度。当前对话模型通过 TokenDance 调用 DeepSeek-V4.1-Flash，负责对话决策/生成，不负责本项目向量化。

## 首次准备，只做一次

本机开发需要 Java 17 或 21、Maven 3.9、Node.js 22。在项目根目录运行：

```powershell
cd E:\SmartServe
powershell -ExecutionPolicy Bypass -File scripts/init-env.ps1
```

脚本保留已有模型 Key 和数据库密码，只补齐缺失的本地初始账号和服务秘密。打开项目根目录 `.env` 查看账号配置，**不要上传该文件**。模型连接由 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 控制；当前配置指向 TokenDance 的 `https://tokendance.space/gateway/v1` 与 `deepseek-v4.1-flash`。本机 Maven 较旧时，在 `.env` 设置 `MAVEN_EXECUTABLE` 为实际 Maven 3.9 的 `mvn.cmd` 路径。本机已下载的依赖缓存不需要手工复制。

管理员用户名默认 `admin`，迁移客户用户名为 `demo`，可查看历史订单。初始密码请打开根目录 `.env`，分别查看 `BOOTSTRAP_ADMIN_PASSWORD=` 与 `BOOTSTRAP_CUSTOMER_PASSWORD=` **等号后面的实际值**；这些大写名称只是配置项名称，不能当成密码输入。普通客户可自行注册；注册及日常改密要求至少 8 个字符，登录兼容已配置的较短初始密码。修改密码会退出所有会话。忘记客户密码请管理员在客户目录重置；修改 `.env` 或重跑初始化脚本不会重置已有数据库中的密码。

账号跟随数据库保存，不跟随启动脚本保存：

| 常用启动方式 | 账号实际保存的位置 |
| --- | --- |
| 常用一：`start.ps1` | 本机 PostgreSQL，端口 5432 |
| 常用二：`start-hybrid.ps1` | Docker PostgreSQL，从本机访问端口 15432 |
| 常用三：全部 Docker | 与常用二相同的 Docker PostgreSQL 和数据卷 |

因此常用二和常用三共享账号及密码，常用一使用独立的一套账号数据。给已有账号改密码时，要更新目标数据库；不会因为三种方式都读取 `.env` 就自动同步已有密码。额外的 `-Mode demo` 使用独立 H2 数据库，也不会自动同步这些账号的后续改密。

## 常用一：本机前后端 + 本机 PostgreSQL

**你读代码、调试业务时优先用这种。** 当前电脑 `.env` 保留了这种配置，PostgreSQL 系统服务先正常运行。Docker Desktop 和原有 Redis 都不是它的依赖。

```powershell
cd E:\SmartServe
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

访问 http://localhost:5173 。`powershell` 启动脚本解释器，`-ExecutionPolicy Bypass` 仅对这个 PowerShell 进程放行脚本，`-File` 后是要运行的脚本。它封装的是 Maven 打包、按需 npm 安装和前后端两个进程启动；没有把 PostgreSQL、Java 或 Node 安装到系统。

这里的 **5173 是网页**，**8080 是 Java 后端 API**。浏览器应打开 5173；打开 8080 不代表前端已经启动。项目使用这套本机方式时，关闭或重开 Docker Desktop 都不会自动启动 Java 和 Vite，必须重新运行上面的 `start.ps1`。只改了 Vue/CSS 且之前已有 JAR，可加 `-SkipBuild` 减少等待。

停止：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop.ps1
```

两个常用附加选项：`-Offline` 关闭远程对话模型和远程追踪，**保留本地 BGE、检索、图与工具业务流程**；`-SkipBuild` 仅在源码和 JAR 的 SHA-256 构建记录一致时复用已有包，否则自动重新构建。本机与混合方式使用同一检查，避免运行旧代码。无需外部数据库试用时，额外加 `-Mode demo`，会临时覆盖为 H2，不修改 `.env`。

## 常用二：本机前后端 + Docker 基础设施

**你学习 RabbitMQ、Redis、pgvector，同时希望在 IDE 调试 Java 时用这种。** 先打开 Docker Desktop，等待引擎就绪：

```powershell
cd E:\SmartServe
powershell -ExecutionPolicy Bypass -File scripts/start-hybrid.ps1
```

脚本启动项目的 PostgreSQL、Redis、RabbitMQ 三个容器，再启动本机前后端。后端临时使用 `postgres` 配置，连接本机端口 15432/16379/5672；`.env` 默认 profile 不变。这里“基础设施”就是数据库、缓存、消息队列，不包含前端和后端应用。

停止本次整套运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop-hybrid.ps1
```

它只停止本项目前后端与三个容器，不停止 Windows PostgreSQL，不停止原有 6379 Redis，不删除数据卷。

## 常用三：全部在 Docker 中运行

**你展示环境可复现部署时用这种。** 先停止本机前后端，打开 Docker Desktop。在 VSCode 项目根目录的终端执行即可：

```powershell
cd E:\SmartServe
powershell -ExecutionPolicy Bypass -File scripts/init-env.ps1
docker compose --profile app up -d --build
```

还是访问 http://localhost:5173 。共五个服务：前端 Nginx、Java 后端、PostgreSQL、Redis、RabbitMQ。`--profile app` 包含应用服务；`up` 创建/启动；`-d` 后台运行；`--build` 按源码构建镜像。前端容器提供构建好的页面，不运行 Vite 开发服务器。

查看状态、跟随后端日志、停止：

```powershell
docker compose --profile app ps
docker compose --profile app logs -f backend
docker compose --profile app down
```

看日志时 Ctrl+C 只退出日志跟随。`down` 停止并移除容器，保留命名数据卷；**不要加 `-v`**。本机方式日志在 `.local/backend.out.log`、`.local/backend.err.log`、`.local/frontend.out.log`，统一启动也能看各自日志。

### 关掉 Docker Desktop 后，怎么判断项目是否仍在运行

Docker Desktop 是运行容器的环境；容器是其中的服务；本机模式的 Java 和 Vite 是 Windows 进程。它们分别有自己的启动、停止方式。Docker Desktop 的容器列表也会显示**已停止**的容器，列表里还有记录不等于正在运行。先等 Docker 引擎显示已启动，再在项目根目录检查：

```powershell
docker compose --profile app ps -a
```

看 `STATUS`：`Up` 才是正在运行，`Exited` 是已停止。若 Docker 命令说连不上引擎，先等 Docker Desktop 真正启动完成。只需继续用本机 PostgreSQL 的话，直接运行 `scripts/start.ps1`，无需 Docker。若要恢复全部 Docker 模式，先确保本机前后端没有占用 8080/5173，再用上面的 `docker compose --profile app up -d --build`；改了前端源码也要重新构建前端镜像。

项目容器设置了 `restart: unless-stopped`，Docker 引擎重新启动时，先前处于运行状态的容器**可能自动恢复**；被你手动停止的容器通常保持停止。因此重开 Docker Desktop 后仍应查看 `STATUS`，不能只看是否出现在列表。想明确停止全 Docker 模式，用 `docker compose --profile app down`；想停止本机模式，用 `scripts/stop.ps1`。前者保留 Docker 数据卷，后者保留本机数据库数据。

## 数据在哪里，端口会冲突吗

| 内容                      | 位置                                                                   |
| ------------------------- | ---------------------------------------------------------------------- |
| 源码、知识 Markdown、图片 | `E:\SmartServe` 下，知识/图片在 `data`                                 |
| demo 数据库               | `E:\SmartServe\backend\data\runtime\smartserve-demo.mv.db`             |
| 本机 PostgreSQL 数据      | PostgreSQL 服务自己的数据目录，SQL `SHOW data_directory;` 查看         |
| Docker PostgreSQL 数据    | `smartserve_postgres-data` 命名卷，挂到容器 `/var/lib/postgresql/data` |
| Docker Redis 数据         | `smartserve_redis-data` 命名卷，容器 `/data`，AOF 已开启               |
| Docker RabbitMQ 数据      | `smartserve_rabbit-data` 命名卷，容器 `/var/lib/rabbitmq`              |
| 隔离评测库和日志          | `.local/evaluation`，与上面三个业务库分开                              |

命名卷由 Docker 的 Linux 引擎存储，通常位于 Docker Desktop 的虚拟磁盘中，**不是 Windows 上直接可打开的数据库文件夹**。查实际卷信息用 `docker volume inspect smartserve_postgres-data`。需要把整块 Docker 数据磁盘迁到 E 盘，使用 Docker Desktop 的磁盘存储设置并按官方迁移流程操作；不会因项目在 E 盘就自动全部存 E 盘。

如确需项目独立可见目录，可以将 Compose 中对应卷映射改为绑定挂载，例如 `E:/DockerData/SmartServe/postgres:/var/lib/postgresql/data`。这是切换数据位置，**原命名卷不会自动复制过去**；先逻辑备份，在新空目录启动并恢复，验证后再决定旧卷去留。不要移动正在运行的 PG 文件，也不要把数据库源目录与工程源码混放。

本机 PG 5432 与项目 PG 15432、原 Redis 6379 与项目 Redis 16379 可以同时存在。容器内部仍用 PG5432/Redis6379，通过容器服务名通信；15432/16379 是你从 Windows 访问的入口。同一种软件有两个独立实例并不矛盾，它们的数据不会自动同步。

## “构建测试”和“启动”有什么区别

`mvn verify` 编译并运行测试；`npm run build` 检查 TypeScript 并生成发布页面。它们成功后会退出，不等于网站在持续运行。`start.ps1` 用构建后的 JAR 启动 Java，同时运行 Vite。修改 Java 需重建，修改 Vue 开发页面通常热更新；Docker 模式改完代码要重新构建应用镜像。

一次只运行一套占用 8080/5173 的前后端。切换方式先停止上一套。三类数据库（H2、本机 PG、Docker PG）的数据相互独立；常用二和常用三连接同一套 Docker PG。在本机 PG 模式买的订单不会出现在 Docker PG 里，这通常不是数据丢失。

## 修改业务后怎样检查两种方式一致

打开 Docker Desktop，保持本机 PG 5432 和项目 Docker PG 15432、Redis 16379、RabbitMQ 5672 可用，再在根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/test-business-modes.ps1
```

脚本在两套 PostgreSQL 中各建全新的 `smartserve_verify_*` 测试库，执行同一套业务、权限和离线 Agent 测试；再用独立消息队列核验 Docker 的 Redis/RabbitMQ。连接用户需要创建测试库及启用扩展的权限。不会清空业务数据库，也不调用付费模型。结果见[跨数据库回归记录](../data/evaluation/results/business-modes.json)，原始日志在 `.local/verification/`。测试库保留供检查；这属于正确性回归，不等于容量压测或正式上线验收。

前端启动时会校验 `/api/status` 的 `businessRulesVersion`，应为 `2.1-20261023`。版本不匹配时更新并重启整套前后端，不能只替换其中一个页面文件。当前 JAR 名称仍是 `smartserve-backend-2.0.0.jar`，不要按业务版本猜文件名。
