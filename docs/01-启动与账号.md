# 启动与账号

适用 ServicePilot，应用包 `2.0.0`，业务规则 `2.1-20261023`。命令均从仓库根目录执行。选择一种方式运行；切换前先停止上一套前后端。

## 方式一：全部 Docker，推荐首次体验

需要 Git、Docker Engine 与 Compose v2；Windows/macOS 可使用 Docker Desktop。无需另外安装 Java、Node、PostgreSQL、Redis 或 RabbitMQ。

```powershell
git clone https://github.com/3911425/smartserve.git
cd smartserve
powershell -ExecutionPolicy Bypass -File scripts/init-env.ps1
docker compose --profile app up -d --build
```

打开 **http://localhost:5173**。首次构建需要下载依赖和本地 BGE 模型，请等待容器就绪。首次在 Windows 运行前需打开 Docker Desktop 并等待引擎启动。

初始化脚本从 `.env.example` 创建 `.env`，仅补齐缺失的四项秘密，不覆盖已有模型 Key、数据库或账号密码。默认禁用远程模型，仍可使用本地 BGE、检索、业务和离线 Agent；需要真实模型时，在 `.env` 设置 `LLM_ENABLED=true`、`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 后重新创建后端容器。默认接口为 TokenDance 的 OpenAI 兼容接口，默认模型 `deepseek-v4.1-flash`；可替换兼容服务。不要提交 `.env`。

Linux/macOS 没有 PowerShell 时，先 `cp .env.example .env`，将 `BOOTSTRAP_ADMIN_PASSWORD`、`BOOTSTRAP_CUSTOMER_PASSWORD`、`SESSION_SIGNING_SECRET`、`MCP_SERVICE_TOKEN` 分别填为独立随机值（每项可用 `openssl rand -hex 24` 生成），再执行同一条 Compose 启动命令。密码不要使用配置项名称。

```powershell
docker compose --profile app ps
docker compose --profile app logs -f backend
docker compose --profile app down
```

三行分别为查看状态、跟随日志、停止并移除项目容器。看日志时 Ctrl+C 只退出跟随；`down` 保留数据卷，**不要加 `-v`，它会删除数据库数据**。修改代码后重新执行带 `--build` 的启动命令。

## 方式二：本机前后端，适合调试

需要 Java 17/21、Maven 3.9、Node.js 22。在 Windows 仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Mode demo -Offline
```

打开 **http://localhost:5173**。脚本依次构建 Java 包、按需安装 npm 依赖，启动 Java 后端与 Vite 前端；不会安装 Java、Node 或数据库。数据用 H2 文件保存，无需 Docker。`-Offline` 关闭远程对话模型与追踪，保留本地向量化和业务流程。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop.ps1
```

需要本机 PostgreSQL 时，在 `.env` 设 `SPRING_PROFILES_ACTIVE=postgres-local`、`DB_USER`、`DB_PASSWORD`；默认数据库 `smartserve`、端口5432，需先建空数据库。自定义连接可设置 `DB_URL=jdbc:postgresql://127.0.0.1:5432/smartserve`。随后运行 `scripts/start.ps1 -Offline`，不加 `-Mode demo`。去掉 `-Offline` 后才采用 `.env` 的模型开关。新克隆的模板默认是 demo，不假设读者已安装 PostgreSQL。

如果 Maven 不在 PATH，在 `.env` 配置 `MAVEN_EXECUTABLE` 的绝对路径。可加 `-SkipBuild` 复用已验证的 JAR；源码或包的构建签名变化时仍会自动重建。8080 是后端 API，5173 才是网页。

## 方式三：本机调试 + Docker 数据库和中间件

同时需要方式一与方式二的环境。在 Windows 打开 Docker Desktop 后：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-hybrid.ps1 -Offline
```

脚本先启动 PostgreSQL、Redis、RabbitMQ 三个基础设施容器，再启动本机 Java 和 Vite。访问地址仍是 **http://localhost:5173**。可在 IDE 给 Java 加断点；需要 IDE 自行运行后端时，应先停止脚本启动的 Java 进程，避免端口冲突。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop-hybrid.ps1
```

它停止本项目前后端及基础设施，不删除卷、不停止系统 PostgreSQL 或其他独立 Redis。全 Docker 与混合方式共享同一套项目 Docker 数据库，因此不能同时启动两套占用5173/8080的应用。日常脚本与评测命令是不同用途，见[验证报告](06-评测与验证报告.md)。

## 配置、数据与账号的对应关系

**启动方式决定进程运行位置，profile 决定后端连接什么。** `.env` 是本机默认值；`-Mode demo`、混合脚本和 Compose 会为本次运行覆盖相关连接，不改写 `.env`。例如本机配置为 postgres-local，Compose 仍显式选择 postgres 并连接容器内数据库。

| profile | 数据保存 | 向量检索 | 任务与缓存 |
| --- | --- | --- | --- |
| demo | H2 文件；向量保存为 JSON 数字数组 | Java 计算余弦 TopK | 本地工作池，无 Redis |
| postgres-local | 本机 PostgreSQL；JSON 数字数组 | Java 计算余弦 TopK | 本地工作池，无 Redis |
| postgres | Docker PostgreSQL + pgvector | 数据库余弦 TopK，带 HNSW 索引 | RabbitMQ + Redis 检索结果缓存 |

三种 profile 默认均使用本地 BGE-small-zh ONNX，512维，并支持 BM25/混合检索。DeepSeek 是对话模型，不负责向量化。Redis 不保存订单资金真值；RabbitMQ 消息只携带持久化任务ID。

| 实例 | 本机访问端口 | 数据与账号 |
| --- | --- | --- |
| 系统 PostgreSQL | 5432 | 独立本机实例 |
| 项目 Docker PostgreSQL | 15432 → 容器5432 | 全 Docker 与混合方式共享 |
| 项目 Redis | 16379 → 容器6379 | 与其他6379实例独立 |
| 项目 RabbitMQ | 5672；管理页15672 | 项目独立实例 |

账号属于数据库。H2、本机 PostgreSQL、Docker PostgreSQL 三套数据不会自动同步；同一份 `.env` 不会同步已有账号的新密码。

管理员名默认 `admin`，初始密码取 `.env` 中 `BOOTSTRAP_ADMIN_PASSWORD=` 后的值。历史演示客户为 `demo`，密码取 `BOOTSTRAP_CUSTOMER_PASSWORD=` 后的值。客户也可以自行注册，不能注册成管理员。普通注册/改密要求至少8字符、BCrypt UTF-8不超过72字节；兼容初始账号配置的较短密码。登录连续失败8次锁定5分钟，会话固定12小时，退出或改密后旧会话失效。

已有数据库不会因为修改 `.env`、重跑初始化脚本或重启服务而重置账号密码。客户忘记密码由管理员重置；管理员凭据恢复需按运维流程处理。完整认证限制见[接口与权限](05-接口与权限.md)。

## 数据文件在哪里，怎么迁移

| 内容 | 位置 |
| --- | --- |
| 知识与演示图片 | 仓库 `data/` |
| 本机 H2 | 仓库 `backend/data/runtime/smartserve-demo.mv.db` |
| 本机 PostgreSQL | PostgreSQL 服务自己的目录，SQL `SHOW data_directory;` 查询 |
| Docker PostgreSQL | 命名卷 `smartserve_postgres-data` → `/var/lib/postgresql/data` |
| Docker Redis | 命名卷 `smartserve_redis-data` → `/data`，启用AOF |
| Docker RabbitMQ | 命名卷 `smartserve_rabbit-data` → `/var/lib/rabbitmq` |
| 隔离评测与日志 | 仓库 `.local/evaluation/`，不提交 Git |

`docker volume inspect smartserve_postgres-data` 显示引擎内路径。Windows Docker Desktop 的 Linux 卷通常位于其虚拟磁盘，不等于源码目录，也不一定是可直接打开的 Windows 文件夹。引擎磁盘迁移通过 Docker Desktop 存储设置处理。

要把某个项目卷改成指定目录，可将 Compose 对应挂载改为绑定挂载，例如 `E:/DockerData/ServicePilot/postgres:/var/lib/postgresql/data`。**修改挂载不会复制旧数据**：先做逻辑备份，在新空目录初始化并恢复，验证后再处理旧卷。不要移动运行中的数据库文件。备份命令及未完成的恢复验证见[运维文档](07-运维与故障演练.md)。

## 排查无法访问

1. 核对当前启动方式，确认打开的是5173；一次只开一套前后端。
2. Docker 用 `docker compose --profile app ps -a` 查状态，`Up` 为运行，`Exited` 为停止；列表中存在容器不代表已启动。
3. 本机日志在 `.local/backend.out.log`、`.local/backend.err.log`、`.local/frontend.out.log`；Docker 用上面的 logs 命令。
4. 关闭 Docker Desktop 会中断容器。重新打开后等引擎就绪，再执行启动命令；`restart: unless-stopped` 不保证手动停止的容器自动恢复。本机 Java/Vite 则由本机脚本控制。
5. `mvn verify` 与 `npm run build` 是构建检查，完成就退出；它们成功不代表网站已经启动。前后端协议须同为 `2.1-20261023`，不要混用旧镜像和新页面。
