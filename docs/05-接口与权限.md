# 接口与权限

接口均以 `/api` 开头，默认同源访问，后端端口8080。HTTP401表示未登录或会话过期，403表示角色/归属/CSRF拒绝，409表示幂等内容冲突或状态/版本已变化，429表示登录锁定或任务配额，400表示输入不合法。统一错误不会回显密钥、SQL或堆栈。

## 登录协议

`POST /auth/login` 接收username/password，返回 `{user,csrfToken}` 并设置 `smartserve_session` Cookie。Cookie为HttpOnly、SameSite=Lax、Path=/api，默认本地HTTP所以Secure=false；公网HTTPS部署必须配置Secure=true。服务器保存随机会话token的SHA-256摘要和到期时间，不保存明文token。

客户端后续带Cookie；写请求另带 `X-CSRF-Token`，令牌由当前会话派生。浏览器跨来源写请求还检查Origin白名单。登录和注册无需已有CSRF，但有Origin检查。退出删除服务端会话；改密撤销该用户全部会话。前端内存只保存CSRF，不在localStorage保存登录token。不要把旧版Bearer演示token拿来调用新API。

## 管理端

| 方法和路径                                | 输入 / 行为                               |
| ----------------------------------------- | ----------------------------------------- |
| GET /admin/customers                      | q/page，按用户名/昵称分页搜索客户，每页20 |
| GET /admin/orders                         | userId/status/page，按客户查订单          |
| POST /admin/orders/{id}/advance           | status=SHIPPED或DELIVERED，version        |
| POST /admin/refunds/{id}/review           | approve/returnedToStock/note/version      |
| POST /admin/customers/{id}/reset-password | password，撤销客户会话，只允许重置客户    |
| GET /admin/feedback                       | 最近100条反馈及问题上下文                 |
| POST /admin/feedback/{id}/review          | note，记录归因，不改知识                  |

页面隐藏入口只是交互，真正的权限在Access及业务服务。管理员订单查询有意具备全局读取权限，客户端客户接口依然核验owner。管理操作是信任边界，不能让模型构造管理员Actor。

## 内部 MCP

`POST /mcp` 使用独立服务token（Authorization: Bearer…）及可信后端提供的Agent/用户上下文，浏览器业务Cookie不能替代它。工具白名单和参数schema在`ToolRegistry`。Nginx拒绝对外代理该路径；本地后端仍有端点，不能公开后端端口后声称它完全不可访问。公网部署须再做网段隔离、服务凭证轮换和访问审计。

## 输入与幂等约定

用户名3至40位、密码至少8字符且UTF-8≤72字节；购买数量1至20；问题最长2000字符；地址最长300字符。`requestKey`由客户端一次业务意图生成，不能携带密钥。

购买会保存请求内容哈希，重复同键不同内容409；run按用户+会话+键去重并检查问题内容；退款按订单唯一；工单按用户+会话+键去重。工单当前返回原记录，不比较同键修改后的表单内容，这个限制不能冒称全接口一致实现请求哈希校验。

服务端参数校验、权限、状态机、数据库唯一约束各解决不同问题。必须分开解释，不能以“用了JWT/加了事务”概括全部安全与一致性。
