# SmartServe 启动运行指南

更新日期：2026年10月21日。此指南对应调整后的端口与启动脚本；此前文档保留作为历史说明，日常启动请以本篇为准。

## 先记住这三件事

下面以VSCode的PowerShell终端为例，普通PowerShell终端也可以。先进入项目目录：

```powershell
cd E:\SmartServe
```

打开网页统一访问 **http://localhost:5173**，后端状态查看 **http://localhost:8080/api/status**。初次运行要等待BGE中文模型加载和知识索引准备，通常需要30～90秒。

三种方式任选一种，切换前先停止当前方式。它们共用前后端端口8080与5173，不能同时启动两套前后端。关闭浏览器或关闭终端窗口，不代表后台程序已经停止。

| 现在想做什么 | 选择 |
|---|---|
| 先看项目、体验业务，不需要Redis和MQ | 方式一，本机运行 |
| 整套放进Docker体验或演示 | 方式二，完整Docker运行 |
| 修改前后端代码，同时体验Redis、MQ和pgvector | 方式三，混合运行 |

## 方式一 日常本机运行

适合：先看项目、体验功能、使用你已有的本机PostgreSQL。**不需要打开Docker Desktop。**

```text
Windows：前端 + 后端 + 你系统安装的PostgreSQL
检索：本地BGE模型 + Java余弦计算
任务：Java工作池；不使用Redis和RabbitMQ
```

前提：本机PostgreSQL服务正在运行；本机smartserve数据库和项目.env中的数据库凭证已配置好。当前这台电脑的.env仍选择postgres-local，没有修改你的密钥和密码。

启动：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

停止：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop.ps1
```

脚本会构建后端JAR，在缺少前端依赖时安装依赖，再在后台启动Java和Vite两个进程。Java、Node与Maven本身需要事先安装；这台电脑的脚本已配置使用Maven 3.9.6。

日志在.local目录，可以持续查看后端日志：

```powershell
Get-Content .local/backend.out.log -Tail 50 -Wait
```

按Ctrl+C只退出这个日志查看。运行失败时也查看.local/backend.err.log和.local/frontend.err.log。

## 方式二 完整Docker运行

适合：体验pgvector、Redis和RabbitMQ全部组件，或验证接近部署形态的运行方式。

```text
Docker：前端 + 后端 + PostgreSQL/pgvector + Redis + RabbitMQ
检索：BGE模型仍在后端运行，相似度搜索交给pgvector
任务：RabbitMQ派发；Redis缓存检索结果
```

先打开Docker Desktop，等引擎运行。项目根目录需要.env；当前电脑已经有，无需复制覆盖。完整Docker方式自动为容器后端选择postgres配置，你不用改本机.env中的postgres-local。

日常启动直接复用已有镜像；没有镜像的电脑会自动构建，首次需要联网下载镜像与依赖：

```powershell
docker compose --profile app up -d
```

查看状态：

```powershell
docker compose --profile app ps
```

等后端等有健康检查的服务显示healthy、前端显示运行后再访问网页。启动命令返回不等于所有服务已经完成初始化。

停止：

```powershell
docker compose --profile app down
```

它停止并移除本项目容器，保留命名数据卷。不要加-v，那个参数会删除项目数据卷。不会停止系统安装的PostgreSQL，也不会停止你原来的独立Redis。

需要查看后端日志时：

```powershell
docker compose --profile app logs -f --tail 50 backend
```

按Ctrl+C只退出日志查看，服务仍然在后台运行。

只有修改了前后端源码、要让容器使用新代码时，执行重新构建并启动：

```powershell
docker compose --profile app up -d --build
```

## 方式三 本机改代码 同时使用完整基础设施

适合：前后端在本机开发，希望同时使用pgvector、Redis和RabbitMQ。前提同样是Docker Desktop引擎已经运行。

```text
Windows：前端 + 后端
Docker：PostgreSQL/pgvector + Redis + RabbitMQ
```

启动：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-hybrid.ps1
```

这个新脚本会先启动并等待本项目的三个基础设施容器健康，再为本次后端进程选择postgres配置和正确端口，然后调用本机前后端启动脚本。它不会改.env，结束后也会恢复脚本所在进程的临时环境变量。

停止整套混合运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop-hybrid.ps1
```

日志与方式一一样在.local目录。前端源码由Vite热更新；修改Java源码后，停止并重新启动，默认会重新构建后端。

如果你想在IDE里自己启动、断点调试Java，而不是用这两个进程启动脚本，只需先运行docker compose up -d，再给Java运行配置指定spring.profiles.active=postgres。此配置已默认连接Windows的15432和16379，工作目录设为E:\SmartServe\backend。不要再同时运行脚本启动的Java实例。

## 已安排好的端口和数据

| 服务 | Windows访问地址 | 用途 |
|---|---|---|
| 系统安装的PostgreSQL | localhost:5432 | 方式一；保留原有实例 |
| 你原来的独立Redis | localhost:6379 | 保留原有容器，项目不自动复用 |
| 项目PostgreSQL容器 | localhost:15432 | 方式二和三 |
| 项目Redis容器 | localhost:16379 | 方式二和三 |
| 项目RabbitMQ | localhost:5672 | 方式二和三 |
| RabbitMQ管理页 | http://localhost:15672 | 账号和密码看本地.env |
| 项目前端 | http://localhost:5173 | 三种方式相同 |
| 项目后端 | http://localhost:8080 | 三种方式相同 |

容器之间仍使用postgres:5432、redis:6379和rabbitmq:5672；15432与16379是给Windows程序连接容器使用的端口。完整Docker运行会自动覆盖内部地址和端口。

方式一的数据在本机数据库。方式二和三使用同一套项目容器数据库，所以二、三之间可以共享会话和订单；它们不会自动复制方式一的数据。

项目容器数据保存在Docker管理的命名卷：smartserve_postgres-data、smartserve_redis-data、smartserve_rabbit-data，可在Docker Desktop的Volumes里查看。项目data目录里的图片和知识文档另行只读挂载给容器。不要让两套PostgreSQL实例共用同一个数据库数据目录。

## 只在需要时使用的两个开关

已经成功构建过、Java代码没有改变，只想更快重新打开本机前后端，可以加-SkipBuild：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -SkipBuild
```

不调用DeepSeek、不导出LangSmith追踪，但仍运行Agent图、本地BGE检索和业务功能，可以加-Offline：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Offline
```

两种开关也适用于start-hybrid.ps1。-Offline不会切换数据库，也不保证首次构建缺少依赖时无需联网。它不表示关闭整个Agent功能。

## 遇到问题先看哪里

端口8080或5173被占用：先停止上一次运行的方式，再启动另一种方式。脚本不会强行结束其他程序。

Docker无法连接：打开Docker Desktop，等引擎启动完成后重试。只有打开一个终端还不够。

页面暂时连不上：先等模型和索引加载，再查看/api/status及对应模式的后端日志。

数据库密码错误：核对.env与目标实例。更改.env不会自动修改已经初始化的数据库卷中的账户密码；不要通过删卷解决，以免丢数据。

问答显示降级：确认.env中的模型开关、Key与网络。启动方式不决定模型是否能访问，BGE本地向量模型与DeepSeek聊天模型也是两个不同部分。
