# Agent 与 RAG 实现

## 哪些部分真正在调用模型

`ModelGateway` 是唯一应用模型出口，使用 LangChain4j 的 OpenAI 兼容客户端通过 TokenDance 调用 DeepSeek-V4.1-Flash（TokenDance 模型 ID `deepseek-v4.1-flash`）。`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY` 在本机 `.env` 或部署环境中提供。产品和售后 Agent 把工具定义和消息传给模型，模型返回 `tool_calls` 后由代码校验并执行，工具结果作为下一轮 `tool` 消息交回模型，模型再选择查询、追问或结束。它们具有有界自主决策循环。

主管节点通常调用模型进行结构化路由；安全升级和明确完整订单号的纯物流问题走规则快捷路径。订单节点调用业务工具并用模板回复，不调用模型。护栏在有模型生成事实时可再调用一次模型审查依据。模型关闭时使用受控检索/业务回复，因此离线流程可运行，但不能把它的通过率当成模型成功率。

举例：“查询订单 SS… 的物流”可为0次；产品咨询常见为主管1次、领域决策若干次、护栏1次，**不是固定3次**。工具本身不必调用远程模型，BGE向量化也不消耗远程模型 Token。503等瞬态重试是额外一次可见尝试。准确次数看任务的 `model_call` 记录。

## 有界循环和权限

默认每个领域最多5轮、每个任务最多10次模型尝试；每个领域工具请求最多8个，知识搜索最多2次，相同工具和相同参数不重复。本机 TokenDance 配置每次 SDK 调用最长90秒、输出预算4096 Token，至多一次显式瞬态重试，四个模型并发许可；这些值由 `MODEL_TIMEOUT_SECONDS` 和 `MODEL_MAX_TOKENS` 调整。预算包含路由、领域、护栏与重试，耗尽后回到受控依据/人工入口。

| 领域        | 工具                                                                                   |
| ----------- | -------------------------------------------------------------------------------------- |
| PRODUCT     | searchKnowledge、getProducts                                                           |
| ORDER       | queryOrderStatus、listMyOrders                                                         |
| AFTER_SALES | searchKnowledge、queryOrderStatus、listMyOrders、checkRefundEligibility、prepareRefund、prepareCancellation |

`prepareRefund` 和 `prepareCancellation` 只形成建议。待发货取消建议引导客户核对订单并确认取消；已送达退货建议引导客户按窗口申请、确认和等待审核。工具目录没有购买、取消执行、改物流、扣款、退款确认或管理员批准。模型不能传 `userId` 选择其他身份；额外参数会拒绝，当前客户由服务器执行上下文传入，业务层再次校验归属。订单工具不返回电话、地址、收件人。管理员在咨询页也不能借工具自由冒充客户。

MCP客户端真实执行 initialize、initialized通知、tools/list、tools/call，经 `/api/mcp` 的HTTP JSON-RPC到工具注册表。内部服务token与可信身份头用于受信后端，不是公开OAuth授权服务；Nginx不对外代理MCP。它是本项目使用的最小协议子集，没有宣称完整多租户MCP平台。

## LangGraph4j 如何组织它们

图包含 supervisor、product、order、service、escalation、guardrail。主管产生多个路由，按产品→订单→售后顺序处理复合意图，结果汇总经过护栏。图状态包括问题、用户、历史摘要、证据、工具事实、卡片和最终结果。节点是代码执行边界，不能根据节点数计算Agent数量。

`JdbcCheckpointSaver` 保存图状态和下一节点，runId充当threadId。恢复时读取同一检查点继续图，而不是开一个全新任务重复整条线路。领域内部工具循环的每一步不单独存图检查点，所以崩溃在领域节点中间可能重跑该节点；只读工具、预算和财务边界用于限制代价。

历史取最近最多9条消息，超过6000字符裁剪。短指代问题会拼接上一条用户问题作为检索查询；这是一种轻量查询改写，**没有实现长期记忆、向量记忆或完整对话摘要服务**。历史多个订单且当前没有明确订单号时不猜订单。未知型号需要澄清。

## RAG 从资料到答案，逐层拆开

1. **来源**：`data/knowledge`下产品手册、FAQ、售后政策、交易与账号，共4份虚构业务资料。资料中的设备App功能是背景手册，不代表网站实现设备控制。
2. **加载**：启动或管理员重建时读Markdown，按二级标题分节，长节按500字符切块、步长450，最多50字符重叠。这是字符切分，不是token精确切分。
3. **元数据**：保留来源文件、标题、产品范围、文档版本、内容hash、模型ID。模型ID不匹配时不复用旧向量；索引revision还纳入检索策略版本，用于缓存失效。
4. **向量化**：本地 `BgeSmallZhEmbeddingModel`，ONNX，512维。资料和问题均由它计算，模型随依赖打包，无须远程Embedding Key。模型最大输入有长度上限，文档块和检索查询都应保持短而明确。
5. **范围过滤**：识别S1/C2/L1/P1/H1/T1及产品中文名。只明确一个型号时检索该产品和通用资料；多型号或未明确型号使用全量。通用FAQ可能仍涉及多个型号，过滤不是语义正确性的证明。
6. **双路召回**：语义一路，JVM余弦或PG余弦距离；词法一路，对中文二元词/英文词计算BM25，真实词频参与评分。各取最多20候选，汇总候选ID。
7. **排序**：vector模式按语义分，bm25模式按归一化BM25分；hybrid为语义0.72、词法0.23、缩放RRF0.05。RRF名次从61起，缺失名次贡献0。这是加权融合，**没有Cross-Encoder神经重排模型**。
8. **证据门槛**：查询须在业务领域，且有Embedding时语义分≥0.63、词法分>0.08；无Embedding测试模式用词法门槛。排序TopK和accepted是不同概念：命中靠前也可能被拒绝。
9. **Agent消费**：只把accepted结果作为知识证据，分配稳定[S1]等引用标识。候选与门槛结果留在事件中，方便区分“没检索到”和“检索到但不敢用”。
10. **生成与审查**：模型读取证据/已核验工具事实，输出答案与追问/升级标志；检查引用白名单并审查事实是否有支持。失败回退到受控摘录或业务提示，不能以“模型说supported=true”保证绝对正确。

Redis缓存的是第8步返回的候选结果，不缓存模型回复、钱包或订单。知识更新后revision变化，旧缓存不命中。当前重建逐块写库并发布内存快照，没有实现多版本原子发布/多实例索引协调；大语料和零停机发布是后续优化。

## AgentOps、LangSmith、评测各做什么

AgentOps在本地显示任务状态、路由、工具、检索候选、检查点事件、模型调用用途/次数/已知Token与耗时，帮助复盘“发生了什么”。不展示隐藏思维，不把内部推理当追踪内容。

`model_call`每次SDK尝试一行。没有收到Token用量的失败请求保存null，不冒充0成本；页面汇总为已知Token，账单以供应商为准。取消后在途调用仍可能计费。LangSmith可选择导出脱敏父链与工具/模型子span，不上传原始问题、正文证据和地址，导出失败不影响本地记录。

评测问“做得是否正确”：检索集测Recall/MRR/误接受，任务集测路由/工具/财务边界，自定义模型评审测答案正确性/忠实性并人工抽查。三类结果分别保存，见[评测报告](06-评测与验证报告.md)。不能因为LangSmith有轨迹就说已经建立完整质量保障体系。

实现参考采用当前依赖版本源码及[LangSmith span字段说明](https://docs.langchain.com/langsmith/run-data-format)、[模型用量记录说明](https://docs.langchain.com/langsmith/cost-tracking)。远程导出、付费评审是否实际验证，以本次报告为准。
